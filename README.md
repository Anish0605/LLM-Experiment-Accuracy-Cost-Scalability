# ICITIIT 2027 — Controlled ETL Benchmark

**Research title:** *AI-Augmented Marketing Analytics: Evaluating Large Language Models in ETL Pipelines for Accuracy, Cost, and Scalability in Small-Scale Deployments*

This Streamlit application compares deterministic rule-based ETL with xAI Grok-assisted normalization on the same controlled records. It is a controlled ETL benchmark, not a return-prediction model.

## Dataset source

- Competition: [E-Commerce Returns: Who Will Send It Back?](https://www.kaggle.com/competitions/retail-return-risk-modeling)
- API identifier: `retail-return-risk-modeling`
- File used: `train.csv` only.
- The app can download `train.csv` directly from Kaggle using the Kaggle API. You do **not** need to upload the dataset to GitHub or manually upload it to Streamlit.
- The competition data may only be accessed after accepting the competition rules on Kaggle. Confirm the competition terms and attribution requirements before publication.
- The competition listing describes 2022–2024 transaction-level records, but the original retailer and real-world provenance have not been independently verified. Do not describe the records as verified commercial transactions without separate evidence.
- `test.csv` and `sample_submission.csv` are not used as ETL ground truth.

## Deploy on Streamlit Community Cloud

Repository entry point: `app.py`.

### Streamlit Secrets

Under your Streamlit app, open **Manage app → Settings → Secrets** and add the following TOML values. Use a real xAI API key from the xAI Console, and your Kaggle API credentials. Never commit keys to GitHub.

```toml
XAI_API_KEY = "your-xai-api-key"
XAI_MODEL = "grok-4.7"
KAGGLE_USERNAME = "anish6"
KAGGLE_KEY = "your-kaggle-api-key"
```

The `XAI_API_KEY` must be an API key from the xAI developer console; a Grok web/chat subscription password is not an API key. Do not send the key in chat or place it in `app.py`. If a key is exposed, revoke it and create another.

To obtain Kaggle API credentials, sign in to Kaggle, open your account settings, find the API section, and create/download an API token (`kaggle.json`). Its username and key values are used above. Do not commit the JSON or credentials to GitHub. Accept the competition rules on Kaggle before trying to download its data.

After saving secrets, reboot/restart the Streamlit app if needed. Click **Test Grok connection** first, then **Download train.csv from Kaggle** in the Dataset workspace. The app invokes the Kaggle CLI to download the competition's `train.csv` into temporary storage and reads it into the session. The file is not committed to GitHub.

Manual upload remains available as a fallback.

## Experiment workflow

1. Fetch `train.csv` directly from Kaggle.
2. Apply the app's documented eligibility rules and select a reproducible sample with a fixed seed.
3. Preserve the original canonical values as ground truth.
4. Generate controlled, reversible formatting variations.
5. Run rule-based and Grok-assisted transformations on identical inputs.
6. Compare field-level accuracy, complete-record accuracy, observed runtime, throughput, token use, API errors, and estimated model service cost.
7. Export audit JSON and record-level CSV; store them securely and do not commit them to the public repository.

## Important interpretation limits

- Controlled formatting/schema repairs do not represent every ETL task faced by a small business.
- A free API allowance may mean no immediate charge, but service-equivalent token cost should be reported separately from actual out-of-pocket expenditure.
- Scalability claims must be based on sizes actually run, not linear projections alone.
- Record the actual model ID, prompt version, dataset fingerprint, seed, timestamp, failures and outputs for reproducibility.
- Do not reuse results from a previous manuscript as results from this new experiment. Only report values generated by the current recorded runs.
- Confirm current xAI model availability and pricing in the developer console before reporting cost estimates in the paper.
